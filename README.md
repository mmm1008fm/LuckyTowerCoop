# LuckyTowerCoop

BepInEx-мод для Lucky Tower Ultimate: второй Ванст — на одном ПК или онлайн (Steam/Spacewar или напрямую по IP).

## Установка
Готовый архив: `dist\LuckyTowerCoop_<версия>.zip` — распаковать куда угодно и запустить `Установить.cmd`
(сам находит игру через Steam/реестр или спрашивает папку; ставит BepInEx 5.4.23.5 + плагин + CoopNet, настройки не трогает).
Удаление — `Удалить.cmd`. Конфиг: `<игра>\BepInEx\config\local.luckytower.coop.cfg` (всё основное меняется и в меню F7).

Сборка:
- плагин: `dotnet build src\LuckyTowerCoop\LuckyTowerCoop.csproj` — dll и LiteNetLib сами копируются в игру (путь: свойство `GameDir`);
- Steam-транспорт: `dotnet publish src\CoopNet\CoopNet.csproj -c Release` — exe + Valve `steam_api64.dll` + `steam_appid.txt` (480)
  копируются в `BepInEx\plugins\LuckyTowerCoop\CoopNet\`.

## Меню F7
- **Онлайн** — создать игру / подключиться (ниже), пересинхронизация, отключение.
- **Настройки** — здоровье врагов и доп. монстры, убийства для воскрешения, воскрешение на новом этаже, подтягивание
  отставшего, подписи над персонажами, управление вторым игроком (локально), пауза при обрыве. Сохраняется сразу.
  У клиента правила только для чтения — их задаёт хост.
- **Игроки** — состояние обоих (жив, руки, золото); «Подтянуть напарника ко мне», «Воскресить сейчас»,
  локально — «Добавить/Убрать второго игрока».
- Над персонажами подписи: онлайн — «Вы» и имя напарника, локально — «1» и «2».

## Онлайн на одном ПК
`Онлайн на одном ПК.cmd` (или `tools\local-online.ps1`) — две копии игры через localhost: слева хост, справа клиент;
клиент запускается, когда хост загрузился, и подключается сам. Клавиатура и мышь — у окна в фокусе; если подключён геймпад,
он всегда управляет клиентом (клавиатура — хостом). Звук — только у окна в фокусе. После закрытия обеих копий режим
экрана игры (полный экран) возвращается сам. Параметры игры: `--coop-host`, `--coop-join IP[:порт]`,
`--coop-window left|right`, `--coop-device auto|keyboard|gamepad|all`, `--coop-devserver`.

### Steam на одном ПК
Нужны второй аккаунт Steam (в друзьях у основного) и Sandboxie-Plus (`winget install Sandboxie.Plus`).
Запуск: `Онлайн Steam на одном ПК.cmd`. Слева хост через основной Steam, справа клиент через второй Steam в песочнице «Steam2».
В первый раз скрипт откроет второй Steam в песочнице: войти вторым аккаунтом с «Запомнить меня» и запустить скрипт снова.
Клиент сам входит в первое лобби друга. Параметры игры: `--coop-steam-host`, `--coop-steam-join [лобби]`.
## Онлайн
- **Хост**: «Создать игру». Через Steam создаётся лобби только для друзей; код лобби можно скопировать в меню и отправить.
- **Клиент**: «Открыть список друзей (Steam)» → «Войти» у друга, либо «Код лобби», либо «Напрямую (IP)» (порт 27015).
- Нужен запущенный Steam у обоих; в статусе Steam видно «Spacewar» — это отдельный процесс `CoopNet.exe`.
- Клиенту не нужно ничего запускать в меню игры: после подключения он сам загрузит сцену хоста.
- **Обрыв связи**: у хоста игра встаёт на паузу и появляется окно «Ждать / Играть одному / Закрыть сессию».
  Персонаж ушедшего падает замертво — вещи можно забрать. Пока сессия открыта, напарник может вернуться
  (клиент переподключается сам, или после перезапуска игры — снова «Войти»): если был жив — появится заново без вещей,
  если был мёртв — останется мёртвым до воскрешения.
- Сейв клиента в онлайне не меняется (играется забег хоста); деревня на время сессии — хоста, после сессии своя.
- Реплики персонажей (субтитры над головой и голос) запускает хост и пересылает клиенту; клиент свои не запускает.
- Сверка: хост раз в 5 с шлёт контрольную сумму комнаты, при расхождении клиент сам просит полную пересинхронизацию.
- Мир (0.3.4): ловушки, рычаги, сундуки, полы, двери-ловушки, свет — состояние идёт от хоста, у клиента их логика выключена;
  урон по врагам виден (текстура), случайные декорации и бомбы одинаковы (общий сид на объект), «свет погас» пересылается.
- Второй игрок (0.3.4): окна выбора (диалог, магазин, джинн, банк) показываются у клиента; выбор — его кнопками 1/2/3 через хост.
  «Начать заново» у клиента — просьба хосту (у хоста окно «Начать заново / Нет»). После смерти камера и свет клиента идут за напарником.
  Превращения (зелье-монстр, джинн) работают для второго: у клиента марионетка меняет тело.
- Задержка «ввод → экран» у клиента = пинг + ~26 мс (показывается в строке статуса).
- 0.3.4: балкон (окна, мусор, птицы, ловушки) и Эвелиус в хабах синхронизированы; объекты с «/» и «#» в именах больше не теряются.

## Управление (локально)
- **Gamepad** (по умолчанию): P1 — клавиатура/мышь и остальные геймпады, P2 — последний подключённый геймпад.
- **Keyboard** (`[Input] P2Device = Keyboard`): P1 — схема «клавиатура + мышь» (WASD, Space, E, F, Q, мышь),
  P2 — стрелки, K прыжок, J атака, L подобрать, U бросок, I использовать, O поменять руки, P выбросить, 7/8/9 варианты
  (дубли на нумпаде 0–6).
- В онлайне каждый играет всеми своими устройствами.

## Правила коопа
- **Двери/проходы/люк — голосованием**: вошёл первый — он прячется, над входом «1/2»; переход, когда второй войдёт туда же.
  Отмена ожидания: «вниз» или прыжок.
- **Смерть**: если жив напарник — забег продолжается. Погибший воскресает, когда живой убьёт `KillsToRevive` монстров
  (или на новом этаже, если `ReviveOnNewFloor = true`). Умерли оба — обычный game over.
  Если умер главный персонаж, главным становится второй (управление у каждого остаётся своё).
- **Предметы**: у каждого свои руки, монеты и кошель на поясе. При переходе в деревню/башню P2 переносится с вещами.
- **Камера** держит обоих; если P2 дольше `LeashSeconds` за кадром — телепортируется к P1.

## Разработка
- `decompiled\` — декомпиляция игры (ilspycmd 9.1), `docs\CODE_MAP.md` — карта классов, `docs\ONLINE.md` — дизайн онлайна.
- Отладка без GUI: `Dev.CommandServer = true` (+ `ForceWindowed`, `RunInBackground` для двух копий), затем `pwsh tools\dev.ps1 "<команда>" [-Port 47801]`:
  `dump`, `where`, `hands`, `doors`, `enemies`, `items`, `maps`, `log N [фильтр]`, `shot имя`,
  `load tower|village|menu`, `loadkeep tower|village`, `spawn`, `despawn`, `kill p1|p2`, `addkills N`, `god [off]`,
  `hold p1|p2 действие [сек]`, `tap p1|p2 действие`, `walkto p1|p2 x`, `spawnitem Имя [p1|p2]`,
  `net host direct|steam`, `net join IP [порт]`, `net joinsteam [лобби]`, `net drop` (имитация обрыва), `net stop`, `net status`, `netents`,
  `net resync`, `net desync N` (клиент «забывает» N объектов — проверка автосверки), `anim [слот]`, `menu 0|1|2|off`.
- `tools\dev-cycle.ps1 [-Tower]` — сборка → запуск → (башня, ожидание P2).
- `tools\net-two.ps1` — сборка → две копии игры (отладочные порты 47800/47801) для теста онлайна на одном ПК;
  `tools\local-online.ps1 -DevServer` — то же через параметры запуска, без правки конфига.
- `tools\soak.ps1 [-Seconds N] [-NoLaunch] [-Desync]` — прогон на износ: случайный ввод обоих, сверка позиций и комнат, сводка ошибок.
- `tools\make-dist.ps1` — Release-сборка и архив с установщиком в `dist\`.

## Архитектура
- P2 — второй экземпляр префаба игрока (`GameManager.m_playerPrefab`), создаётся выключенным, получает свой клон `CommandPattern`.
- Ввод P2 — системный игрок Rewired (в игре настроен один Rewired-игрок, а InputManager стартует раньше BepInEx).
- ИИ и код предметов обращаются к «игроку» через `Player.VonWansts[0]`/`GameManager.Player`: на время апдейта врага
  подставляется ближайший живой игрок, на время действий P2 — сам P2 (`Patches/AiTargetPatches.cs`, `ActingAsPatches.cs`).
- Онлайн: хост-авторитет, клиент-зеркало (`Net/`): см. `docs/ONLINE.md`.

## Известные ограничения
- Часть ловушек, подсказок и реплик компаньонов реагирует только на главного персонажа.
- Слои глубины (балконы, лаборатории) общие: если P2 наступит на переключатель слоя, он сменит слой и для P1.
- Зелье превращения в монстра и бутылка возрождения корректно работают только для главного персонажа.
- Онлайн: у клиента задержка ввода = пинг + ~26 мс; не передаются выражение глаз врагов и видео взрыва башни (бочка с порохом).
- Онлайн: пещеры после выхода из башни генерируются игрой без общего сида — могут разойтись (в работе).
- Реальные геймпады и Steam-подключение двух разных аккаунтов автотестами не проверены.
